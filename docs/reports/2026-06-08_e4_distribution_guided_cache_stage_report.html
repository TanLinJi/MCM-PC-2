MCM-PC E4 分布引导 Cache 阶段性实验说明

项目：MCM-PC-2 / Point-Cache 日期：2026-06-08 对象：ULIP × ModelNet-C severity=2 报告：E4-A/B/C 阶段结论

本文整理 E4 分布引导 GPA-Cache 的实验设定、流程、代码边界、结果对比、机制解释与专家审查补充。数值来自本地 summary.csv 与 gpa_stats/*.json。

1. 阶段结论

TL;DR

E4-C 可以作为当前阶段性正结论。它将视觉分布从 E4-B 的“当前缓存截面”修正为“被正缓存接受过的可信历史样本累计分布”，在 7 个 ModelNet-C severity=2 corruption 上达到 54.50 平均准确率，超过 E2 / Point-Cache 的 54.00，也超过 E3-V2-C union center 的 54.04。

3. 方法流程

3.0 从“原型中心”到“分布裁判”

E3 / E3-V2-C 的核心判断是“新样本是否更接近类别原型中心”。其中视觉中心来自当前可信视觉缓存，文本中心来自同一类别多条 prompt embeddings 的平均；若做文本-视觉联合中心，则应先得到固定文本中心和在线视觉中心，再做加权融合。这个路线的问题是：一个中心点很难表达类内多样性，尤其在几何变化、局部缺失和尺度变化下容易把正常样本推离中心。

E4-C 不再把文本中心直接拉入欧氏原型中心，而是把文本端和视觉端都表示为类别分布。视觉端保留 visual_mean 与 visual_var，文本端保留 text_mean 与 text_var。替换判断从“离中心更近”改为“在该类视觉历史分布下更合理，并且与文本 prompt 分布不过分冲突”。因此 E4-C 的所谓“中心”只是分布参数的一部分，不再是唯一决策依据。

3.1 原始 Point-Cache 组件

  • Global Entropy Cache：按预测类别维护低熵全局特征，用于 global cache logits。
  • Local Cache：维护 patch-level local features，用于 local cache logits。
  • Negative Cache：按原 Point-Cache 逻辑维护负缓存；本次 E4-C runner 中在 test loop 内按 entropy 区间在线更新，最终从 logits 中减去。

3.2 GPA-Cache 组件

GPA-Cache 的目标不是直接替代 Global Entropy Cache，而是控制哪些样本的 local patch features 可以进入 GPA-local-cache。也就是说，局部缓存由全局样本的可信程度来控制。

如果样本进入 GPA-Cache:
    对应 patch_centers 进入 GPA-local-cache
否则:
    patch_centers 不进入 GPA-local-cache

3.3 E4-C 的文本-视觉分布

E4-C 同时维护两个类别分布：

  • text_dist[c]：固定分布，由类别 c 的 prompt-level embeddings 构成；测试期间不更新。
  • visual_dist[c]：在线分布，只累计曾被 Global Entropy Cache 或 GPA-Cache 接受过的可信视觉样本。

当前实现中，这两个分布都采用单峰对角高斯近似。对类别 c，视觉分布和文本分布分别写作：

p_v(x | c) ≈ N(x | μ_c^v, diag((σ_c^v)^2))
p_t(x | c) ≈ N(x | μ_c^t, diag((σ_c^t)^2))
这里的单峰对角高斯只建模每类一个均值和一组逐维方差；它不是多峰分布，也没有建模特征维度之间的协方差。

其中：

  • x：当前测试样本的全局特征向量。
  • c：当前样本被 zero-shot / cache 流程预测到的类别。
  • μ_c^v：类别 c 的视觉历史分布均值，由被正缓存接受过的视觉特征在线累计得到。
  • (σ_c^v)^2：类别 c 的视觉历史分布逐维方差。
  • μ_c^t：类别 c 的文本 prompt 分布均值，由该类 64 条 prompt embeddings 计算得到。
  • (σ_c^t)^2：类别 c 的文本 prompt 分布逐维方差。

视觉和文本分布得分采用负的、按维度平均的、方差归一化平方距离：

s_v(x,c) = - (1 / d) Σ_{i=1}^{d} ((x_i - μ_{c,i}^v)^2 / ((σ_{c,i}^v)^2 + ε_v))
s_t(x,c) = - (1 / d) Σ_{i=1}^{d} ((x_i - μ_{c,i}^t)^2 / ((σ_{c,i}^t)^2 + ε_t))
s_joint(x,c) = s_v(x,c) + λ_t · s_t(x,c)
得分越高表示越符合该类别分布；当前 ε_v=ε_t=1e-4，λ_t=E4_TEXT_SCORE_WEIGHT=0.1。

其中：

  • d：特征维度。
  • x_i：测试样本特征第 i 维。
  • μ_{c,i}^v / μ_{c,i}^t：类别 c 的视觉/文本均值第 i 维。
  • (σ_{c,i}^v)^2 / (σ_{c,i}^t)^2：类别 c 的视觉/文本方差第 i 维。
  • ε_v / ε_t：数值稳定项，防止方差过小导致除零或异常放大。
  • λ_t：文本分布得分权重，控制文本 prompt 分布对 GPA-Cache 替换判断的影响强度。
visual_score(x, c) = -mean((x - visual_mean_c)^2 / (visual_var_c + eps_v))
text_score(x, c)   = -mean((x - text_mean_c)^2 / (text_var_c + eps_t))
joint_score(x, c)  = visual_score(x, c) + lambda_text * text_score(x, c)

这里的文本端不是把文本均值直接混入视觉中心，也不是把 64 条 prompt 先压成一个单点原型后参与欧氏中心平均。实现中每类文本 prompt embeddings 构成固定 text_dist[c]，保存该类文本均值和对角方差；测试期间只通过 text_score 以 E4_TEXT_SCORE_WEIGHT=0.1 参与 GPA-Cache 替换判断。文本分布不更新，也不直接改变最终 logits。

3.4 GPA-Cache 替换规则

满缓存时，E4-C 的替换判据可以写成：

replace(x_new, x_old, c) = 1
iff H(x_new) < H(x_old) and s_joint(x_new,c) > s_joint(x_old,c)
x_old 是当前 GPA-Cache[c] 中熵最高的旧样本；H(·) 是预测熵。也就是说，新样本必须更低熵，并且在文本-视觉联合分布下得分更高，才允许替换。
如果 GPA-Cache[c] 未满:
    直接加入 GPA-Cache[c]
    同步加入 GPA-local-cache[c]
    更新 visual_dist[c]

如果 GPA-Cache[c] 已满:
    x_old = GPA-Cache[c] 中最高熵样本
    如果 entropy(x_new) < entropy(x_old)
       且 joint_score(x_new, c) > joint_score(x_old, c):
           用 x_new 替换 x_old
           同步替换 GPA-local-cache[c]
           更新 visual_dist[c]
    否则拒绝
重要边界E4-C 中，被正缓存接受过但后来被容量机制淘汰的样本仍保留在历史分布中；但从未进入 Global Entropy Cache 或 GPA-Cache 的候选样本不会参与分布。

3.5 实现核对

检查项当前实现解释
文本分布构建build_text_distribution_once() 为 40 类分别构建 prompt-level 分布，每类 64 个 prompt embeddings。文本分布固定，不参与在线更新；保存均值和方差，不只是一个单一文本中心。
视觉分布更新来源_update_visual_distribution() 只在 GPA add、GPA replace、Entropy add/replace 成功后调用。未被正缓存接受的候选样本不会污染分布。
重复计数处理通过 _feature_key() 对同一 tensor 去重。同一样本若同时被 GPA-Cache 与 EntropyCache 接受，只计入视觉历史分布一次。
替换时机GPA-Cache 未满时直接加入；已满后才计算 joint score 并尝试替换最高熵旧样本。这保持了 E3-V2-C / E4-A 的初始化逻辑，避免早期分布样本不足导致无法启动。
最终预测公式final_logits = clip_logits + entropy_global_logits + gpa_local_logits - negative_logitsE4-C 只改变 GPA-local-cache 的准入与替换，不改变 Point-Cache 的最终加权公式。

当前 E4-C 的最终 logits 公式为：

logits_final = logits_zs + logits_entropy-global + logits_gpa-local - logits_negative
logits_cache(x) = α · Σ_j exp[-β(1 - x^T k_j)] · y_j
α 控制 cache logits 强度，β 控制相似度核的尖锐程度。当前 ModelNet-C 配置中 positive cache 使用 α=2.0, β=3.0，negative cache 使用 α=0.117, β=1.0。

其中：

  • logits_zs：zero-shot 文本分类器输出。
  • logits_entropy-global：Global Entropy Cache 产生的全局 cache logits。
  • logits_gpa-local：由 GPA-Cache 准入控制的 local cache logits。
  • logits_negative：Negative Cache 产生的反向修正 logits。
  • k_j：cache 中第 j 个特征。
  • y_j：cache 中第 j 个特征对应的类别 one-hot 或 negative mask。

3.6 运行时序

  1. 构建文本分布：每个 corruption 开始前复用固定 classnames 与 prompt 模板，为 40 个类别构建 text_dist。
  2. 预构建正缓存：遍历 test loader，构建 entropy_cache、gpa_cache 和 gpa_local_cache，直到 Global Entropy Cache 达到容量上限或数据遍历结束。
  3. 测试时在线更新：每个测试样本先尝试更新 GPA-Cache 和 EntropyCache，再根据当前缓存计算 global/local/negative logits。
  4. 保存诊断统计：每个 corruption 结束后保存最终 accuracy、缓存类别覆盖、visual distribution 摘要和 GPA 替换事件。

6. 机制诊断

6.3 为什么 add_global 没有保持 E4-A 的强收益？

E4-A 在 add_global_2 上达到 50.73，是 E4-A 最亮眼的一项；E4-C 在该项回到 47.81，与 E2 持平。说明 accepted-history 分布增强了整体鲁棒性，但对添加型全局外点的强过滤能力不如 E4-A 的 GPA-only 视觉历史分布。一个合理解释是：EntropyCache accepted 样本进入历史分布后扩大了分布覆盖范围，也可能减弱了对 add_global 外点的严格排斥。

6.4 为什么 rotate 仍然失败？

rotate_2 是 E4-C 唯一低于 E3-V2-C 的 corruption。旋转改变的是几何姿态与特征分布方向，accepted-history 单一对角分布仍可能把某些旋转下的正常样本视为低符合度样本。这个现象说明 E4-C 虽然比 E4-B 更合理，但仍不是几何变换的完整解法。

7. 专家审查与补充说明

7.1 本文档初稿可能遗漏的问题

  • 未区分 E4-C 的收益来源：E4-C 同时使用 EntropyCache accepted 和 GPACache accepted 样本，当前结果不能判断哪一个来源贡献更大。
  • 未证明文本分布有正收益：E4-C 比 E4-A 更好，但这可能主要来自 accepted-history visual distribution，而不是 text_dist。需要 E4_TEXT_SCORE_WEIGHT=0 消融。
  • 未证明对角高斯形式最优：当前 score 只用逐维均值和方差，未建模特征维度相关性；它是最小可验证实现，而不是最终概率建模形式。
  • 替换规则仍偏保守：所有 corruption 的平均 joint margin 都为负，说明大多数候选样本仍被旧缓存样本压制；收益来自少量更可靠替换，而不是大规模 cache 重构。
  • 只在 severity=2 上验证：当前结论不能直接推广到 severity=0/1/3/4 或 all35 全 corruption。
  • 只在 ULIP × ModelNet-C 上验证：不能直接声称跨 backbone 或跨数据集有效。
  • 没有统计显著性：目前是单次 seed / 单配置实验，没有多 seed 方差。

7.2 补充后的更严谨结论

严谨表述E4-C 目前可以作为“ULIP × ModelNet-C severity=2 下的阶段性正结果”，而不是最终方法结论。它证明 accepted-history distribution 是比 current-cache snapshot distribution 更合理的分布来源，并在 7 corruption 平均上超过 E2/E3-V2-C。

7.3 审稿人可能追问的问题

问题当前回答需要补的证据
为什么 E4-C 优于 E4-B？E4-B 使用当前缓存截面，shot=3 导致每类样本过少；E4-C 累计正缓存接受历史，平均每类约 13.5 到 14.6 个样本。保留 E4-B 的 add_global 负结果，并补一组小规模 E4-B 多 corruption 或只在文中作为失败分支。
文本分布是否真的有帮助？现在不能确定。E4-C 的提升可能主要来自 accepted-history visual distribution。跑 E4_TEXT_SCORE_WEIGHT=0 和权重 sweep。
EntropyCache accepted 是否引入污染？add_global 从 E4-A 的 50.73 回落到 47.81，提示 Entropy accepted 可能放宽了外点噪声下的分布边界。跑 Entropy-only / GPA-only / union 三组 accepted-source 消融。
为什么 rotate 仍然弱？单一对角分布不能充分表达旋转引起的几何姿态变化；局部缓存也可能引入姿态不一致的 patch evidence。做 rotate 专项：统计被替换样本的 visual/text score 分布和错误类别转移。
能否写进论文主方法？可以作为候选主线，但必须先补消融；目前更适合作为“accepted-history distribution improves distribution-guided cache purification”的阶段性结论。完成 P0/P1 后再决定是否升级为主方法。

7.4 当前最可信的论文叙事

  1. E3 单中心原型方法可以改善某些外点噪声，但对几何变化不稳定。
  2. E4-A 说明“视觉分布替代单中心”有潜力，但 GPA-only 视觉分布整体不稳定。
  3. E4-B 说明“当前缓存截面分布”在小 shot cache 下会过窄，导致错误拒绝低熵候选。
  4. E4-C 说明“正缓存接受过的历史可信样本”更适合作为类别分布来源，能够保留多样性并避免未接受样本污染。
  5. 下一步论文叙事的关键不是继续盲目加模块，而是证明“可信历史分布”“文本分布约束”“accepted source 选择”各自的独立贡献。

8. 下一步计划
