# D002: Prompt Source Policy for E1 Text Prototype Enhancement

## Date

2026-06-03

## Background

Point-Cache constructs text prototypes from class names and prompt templates. Its visual-side adaptation is dynamic because global and local caches are updated with online test samples. However, its text-side representation is mainly based on a fixed manual prompt ensemble.

The original manual prompt ensemble contains many 2D image-style templates, such as photo-style, blurry-photo-style, cropped-photo-style, and painting-style prompts. These templates are useful for reproducing the original Point-Cache baseline, but they may not be optimal for 3D point cloud recognition.

E1 therefore focuses on text-side processing before modifying the cache mechanism.

## E1 Definition

E1 is defined as:

**Text Prototype Enhancement with Point-Cloud-Aware and Dynamically Generated Prompts**

The goal is to study whether text prototypes can be improved by using point-cloud-aware templates and DeepSeek-generated class-level descriptions.

## Terminology

To avoid ambiguity, all prompt-source names used in E1 are defined here.

### manual_full

`manual_full` means the original full manual prompt set used by Point-Cache.

中文理解：`manual_full` 指 Point-Cache 原始完整手工模板集合，也就是 baseline 默认使用的固定 prompt templates。它包括点云相关模板，也包括大量 2D image-style templates such as photo-style or painting-style prompts.

This is the E0-compatible baseline prompt source and must remain unchanged.

### manual_3d

`manual_3d` means a point-cloud-aware subset filtered from `manual_full`.

中文理解：`manual_3d` 指从原始手工模板中筛选出的点云/3D 相关模板子集。

Filtering principle:

- keep prompts related to point cloud, 3D, object, shape, model, geometry, or scene;
- remove prompts that are clearly image-style, such as photo, image, picture, painting, sketch, cartoon, blurry, cropped, or black-and-white descriptions.

`manual_3d` is not a replacement for `manual_full`. It is an E1 comparison setting.

### deepseek_static

`deepseek_static` means a static prompt source generated by DeepSeek and saved as JSON before experiments.

中文理解：`deepseek_static` 指提前用 DeepSeek 生成并保存为 JSON 的固定文本描述。实验时只读取，不再动态调用 API。

This setting is useful for reproducibility and for comparison with existing Point-Cache-style fixed LLM prompts.

### deepseek_dynamic_init

`deepseek_dynamic_init` means DeepSeek prompts generated at the beginning of each experiment run.

中文理解：`deepseek_dynamic_init` 指在每次实验启动时，根据当前数据集的候选类别名称调用 DeepSeek 生成文本描述。生成后保存并冻结，整个测试流中不再更新。

The generation is class-level, not sample-level.

Allowed information:

- dataset candidate class names.

Disallowed information:

- test sample ground-truth labels;
- test point cloud content;
- individual test sample predictions.

### manual3d_deepseek_dynamic_init

`manual3d_deepseek_dynamic_init` means a mixed prompt source combining `manual_3d` and `deepseek_dynamic_init`.

中文理解：`manual3d_deepseek_dynamic_init` 指“点云手工模板分支 + DeepSeek 动态生成描述分支”的融合版本。

This is the main E1 method candidate.

## Core Decision

The original Point-Cache prompt templates must not be deleted.

They are retained as the E0-compatible baseline text setting.

E1 introduces additional prompt sources for controlled comparison, rather than overwriting the original template list.

## Dynamic Prompt Rule

E1 uses dynamic-init prompt generation, not dynamic-online prompt generation.

Allowed in E1:

1. read dataset candidate class names before inference;
2. call DeepSeek to generate class-level point-cloud-aware descriptions;
3. save generated prompts to the experiment result directory;
4. build text prototypes;
5. run zero-shot or Point-Cache inference with frozen text prototypes.

Not allowed in E1:

1. do not call LLM for each test sample;
2. do not generate prompts based on a single test sample;
3. do not use ground-truth labels;
4. do not expose point cloud content to the LLM;
5. do not update prompts during the test stream.

Dynamic-online prompt generation is left as future work.

## Main E1 Fusion Formulation

The preferred E1 formulation is branch-level weighted fusion, rather than forcing a fixed total number of prompt strings.

Default formulation:

    text_prototype =
        static_weight * mean(manual_3d embeddings)
        + dynamic_weight * mean(dynamic DeepSeek embeddings)

Default setting:

- static branch weight: 0.75
- dynamic branch weight: 0.25
- dynamic prompt count: 25 prompts per class.

This avoids forcing `manual_3d` to contain a fixed number of templates.

## API Key Policy

DeepSeek API keys must never be committed to the repository.

For convenience, the project may use a fixed local key file:

    Point-Cache/llm/secrets/deepseek_api_key.txt

This file is local-only and must be ignored by git.

The implementation should read the API key in the following order:

1. read from `Point-Cache/llm/secrets/deepseek_api_key.txt` if the file exists;
2. otherwise read from the environment variable `DEEPSEEK_API_KEY`;
3. if neither exists and dynamic prompts are enabled, raise an error.

A tracked template file may be provided later, for example:

    Point-Cache/llm/secrets/deepseek_api_key.example.txt

The example file must not contain a real API key.

## Reproducibility Rules

Generated prompts must be saved under the corresponding experiment result directory, for example:

    Point-Cache/results/mcmpc/E1_tpe/prompts_used.json

The saved prompt file should include:

- prompt source;
- LLM provider;
- LLM model name;
- generation time;
- prompt budget;
- class names;
- generated prompts;
- generation configuration.

This ensures that dynamic prompts remain auditable and reproducible after generation.

## E1 Experiment Order

### Stage 1: Zero-shot prompt comparison

Compare:

- manual_full;
- manual_3d;
- deepseek_dynamic_init;
- manual3d_deepseek_dynamic_init.

### Stage 2: Point-Cache prompt comparison

If Stage 1 shows a meaningful trend, extend the comparison to:

- zero-shot;
- zero-shot + global cache;
- zero-shot + global cache + local cache.

## Initial Priority Settings

Initial E1 settings:

- ULIP × ModelNet-C all35;
- ULIP-2 × ModelNet-C all35;
- Uni3D × ScanObjNN-C hardest all35.

## Relationship to E0

E0 remains the Point-Cache baseline reproduction and analysis.

`manual_full` is the E0-compatible text setting.

E1 must not overwrite E0 results.
